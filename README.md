# Netology Cat Backup — резервное копирование картинок кошек

Курсовая работа «Резервное копирование» курса «Специалист по искусственному
интеллекту» (Нетология), группа **AIE-9**.

Программа получает картинку кошки с вашей надписью через
[CATAAS](https://cataas.com/) и сохраняет её в папку `AIE-9` на
Яндекс.Диске. Картинка загружается **по воздуху**: Яндекс.Диск сам скачивает
её по ссылке, на компьютер файл не сохраняется. Сведения о загруженном файле
и его фактическом размере записываются в `result.json`.

Оригинальное задание:
<https://github.com/netology-code/pyapi-diplom-basic/tree/add_cats>
(основной вариант — кошки с текстом).

## Как это работает

1. Пользователь вводит текст надписи (например, `Привет`).
2. Программа формирует ссылку `https://cataas.com/cat/says/<текст>`; пробелы,
   кириллица и спецсимволы корректно кодируются.
3. Проверяется доступ к Яндекс.Диску и действительность токена.
4. Создаётся папка `AIE-9` (если она уже есть — используется существующая).
5. Запускается загрузка по URL (`POST /v1/disk/resources/upload`).
   Ответ `202` означает лишь запуск операции, поэтому программа ограниченное
   время (по умолчанию до 60 секунд) проверяет её статус до `success`.
6. Программа убеждается, что файл появился на Диске, и берёт размер из его
   метаданных. Если Диск определил формат, отличный от JPEG, файл
   переименовывается в правильное расширение (`.png`, `.gif`).
7. Запись добавляется в `result.json`.

Имя файла — это текст надписи. Символы, недопустимые в именах файлов
(`< > : " / \ | ? *`), заменяются на `_`. Если файл с таким именем уже есть,
он **не перезаписывается**: новый файл получает имя `Привет (1).jpg`,
`Привет (2).jpg` и т. д.

## Технологии

- Python 3.11 или новее (проверено на Python 3.13);
- [requests](https://pypi.org/project/requests/) — HTTP-запросы;
- [python-dotenv](https://pypi.org/project/python-dotenv/) — чтение `.env`;
- `logging` из стандартной библиотеки — вывод хода работы;
- [pytest](https://pypi.org/project/pytest/) — тесты;
- REST API Яндекс.Диска, API CATAAS.

## Установка

```bash
git clone https://github.com/Supaplex777/netology-cat-backup.git
cd netology-cat-backup

python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS / Linux:
source .venv/bin/activate

pip install -r requirements.txt
```

## Получение OAuth-токена Яндекс.Диска

1. Откройте [Полигон Яндекс.Диска](https://yandex.ru/dev/disk/poligon/) и
   войдите в свой Яндекс ID.
2. Нажмите кнопку **«Получить OAuth-токен»** и подтвердите доступ.
3. Скопируйте токен. Это пароль к вашему Диску: никому его не пересылайте и
   не публикуйте в GitHub.

## Настройка токена

Есть три безопасных способа — выберите любой.

**Файл `.env`** (удобно на своём компьютере):

```bash
cp .env.example .env      # Windows: copy .env.example .env
```

Откройте `.env` в редакторе и впишите токен после `YANDEX_DISK_TOKEN=`.
Файл `.env` указан в `.gitignore` и в репозиторий не попадёт.

**Переменная окружения** на время сеанса терминала:

```bash
export YANDEX_DISK_TOKEN="ваш_токен"           # macOS / Linux
$env:YANDEX_DISK_TOKEN = "ваш_токен"           # Windows PowerShell
```

**Ввод при запуске**: если токен не задан, программа попросит его ввести;
символы при этом не отображаются на экране.

## Запуск

```bash
python main.py
```

Программа спросит текст надписи. Текст можно передать и сразу:

```bash
python main.py "Привет, котик"
```

Пример вывода:

```text
14:12:51 [INFO] Запуск резервного копирования
14:12:51 [INFO] Готовлю ссылку на картинку с надписью «Привет, котик»
14:12:51 [INFO] Проверяю доступ к Яндекс.Диску
14:12:52 [INFO] Папка «AIE-9» уже существует
14:12:52 [INFO] Запускаю загрузку на Диск по URL: AIE-9/Привет, котик.jpg
14:12:52 [INFO] Жду, пока Яндекс.Диск скачает картинку
14:12:54 [INFO] Статус операции (проверка 2): success
14:12:54 [INFO] Проверяю, что файл появился на Диске
14:12:54 [INFO] Файл загружен: Привет, котик.jpg, размер 48213 байт
14:12:54 [INFO] Сведения сохранены в result.json

```

Коды завершения: `0` — успех, `1` — ошибка Яндекс.Диска или сети,
`2` — некорректный текст.

## Результат

- На Яндекс.Диске в папке `AIE-9` появляется картинка, названная по тексту
  надписи.
- В `result.json` (UTF-8, кириллица без экранирования) добавляется запись.
  При повторных запусках записи накапливаются. Если загрузка не удалась,
  запись не создаётся.

Пример формата (значения условные):

```json
[
  {
    "file_name": "Hello.jpg",
    "size": 152430
  }
]
```

`size` — размер в байтах, полученный из метаданных Яндекс.Диска после
подтверждения загрузки.

## Тесты и проверки

Тесты не обращаются к реальным API и не требуют токена.

```bash
python -m pytest
```

Проверка стиля PEP8 (необязательно, нужен [ruff](https://docs.astral.sh/ruff/)):

```bash
pip install ruff
ruff check .
```

Тесты проверяют: формирование URL и кодирование кириллицы, пустой и слишком
длинный ввод, имена файлов, создание и наличие папки, асинхронную загрузку,
ошибки HTTP (401, 403, 429, 5xx), тайм-ауты и сетевые сбои, повторные имена,
получение размера, JSON-отчёт, отсутствие токена в выводе и файлах проекта.

## Известные ограничения

- CATAAS каждый раз выдаёт случайную кошку, поэтому размер файла при каждом
  запуске разный.
- Если CATAAS недоступен, Яндекс.Диск вернёт статус операции `failed`, и
  программа сообщит об ошибке.
- Ожидание загрузки ограничено 60 секундами (`UPLOAD_WAIT_SECONDS` в
  `config.py`). Если Диск не успел, файл может появиться позже — программа
  сообщит об этом и не создаст запись в отчёте.
- Длина надписи ограничена 100 символами.
